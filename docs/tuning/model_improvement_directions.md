# 模型改进方向

> 整理日期：2026-05-07  
> 基于数据：v1 / v1.0.1 / v1.0.2 / v1.0.2.1 信号分析报告（截至 2026-05-06）  
> 核心前提：当前所有版本方向准确率均低于随机猜测（50%），优化目标是提升模型本身的预测准确率，而不是加策略过滤器掩盖问题。

---

## 问题 0（根本性）：训练标签与实盘评估不一致

### 现状

`src/features/labels.py`：

```python
HORIZON = 30            # 30根1m K线 = 30分钟
entry_threshold = 0.010 # 1% 涨幅才算正样本（y_class=1）
```

实盘 TP/SL 实际参数：
- TP ≈ +0.3~0.4%
- SL ≈ −0.3%
- 平均解仓时间：bar+1.5~6（7~30分钟）

### 问题

模型被训练成回答 **"未来 30 分钟内价格会涨超 1% 吗？"**，  
但实盘评估的是 **"价格先到 +0.3% 还是先到 −0.3%？"**  

这是两个不同的问题。即使模型把第一个问题回答对了，对第二个问题也没有预测力。

`thr005`（v1.0.2.1 使用 0.5% 阈值）方向正确，但仍比实盘 TP 宽一倍。

### 建议

将 `y_class` 的标签逻辑改为：

```python
# 正样本 = 价格先触及 tp_pct 而非 sl_pct
y_class = 1  if  ymax >= tp_pct  AND  (ymin 触及 sl_pct 之前 ymax 先到达)
y_class = 0  otherwise
```

或者更简单的近似版本：在实盘使用的窗口（比如 36 根 5m = 3h）内，`ymax ≥ tp_pct` 且 `ymin > -sl_pct`。

**预期收益**：直接消除训练-评估的目标不一致，这可能是准确率低于随机猜测的核心原因。

## 问题 1（高）：1h 特征极度稀疏

### 现状

`src/features/timeframe.py` 中 1h 特征只有一个：

```python
def _add_medium_features(out, df, suffix):
    mhist = macd_histogram(cl)
    out[f"macd_zone{suffix}"] = np.sign(mhist)   # 只有 {-1, 0, +1} 三个值
```

1 个 1-bit 信号 vs 4h 有 7 个特征（EMA200、deviation、trend_score、ema_slope、rsi_regime、adx）。

### 问题

从实盘报告可以看出，`1h=DN` 时 LONG 大量失败，`1h=UP` 时 SHORT 大量失败——1h 趋势对 5 分钟方向有巨大影响，但模型几乎没有这方面的信息。

### 建议

将 `_add_medium_features` 扩充到与 4h 相似的密度：

| 新增特征 | 说明 |
|---------|------|
| `rsi14_1h` | 超买超卖状态 |
| `bb_position_1h` | 价格在布林带中的位置 |
| `roc5_1h` | 1h 级别的动量方向和强度 |
| `ema_cross_1h`（ema9/ema21） | 短期趋势方向 |
| `atr_zscore_1h` | 波动率水平（是否处于异常波动期）|

**预期收益**：给模型明确的中期市场背景，减少"逆 1h 趋势 LONG"类误触发。

## 问题 2（中）：缺乏价格结构特征

### 现状

当前特征全部是动量类（涨速、成交量加速、技术指标值），没有"当前价格在近期高低点的哪个位置"的信息。

### 问题

均值回归模式（实盘数据已证实 AGST 胜率 > WITH 胜率）需要"价格相对近期区间的位置"才能发挥，但模型没有这个参考系。

### 建议

加入以下特征（仅 5m 层即可）：

```python
# 近期高低点距离
hi20 = hi.rolling(20).max()
lo20 = lo.rolling(20).min()
range20 = hi20 - lo20
out["dist_to_high20_5m"] = (hi20 - cl) / range20    # 距离近期高点的比例
out["dist_to_low20_5m"]  = (cl - lo20) / range20    # 距离近期低点的比例
out["position_in_range20_5m"] = (cl - lo20) / range20  # 在近期区间内的位置 [0,1]
```

更进一步可加入：前 N 根 K 线是否出现了 pinbar（wick ratio > 2×body）等形态标志。

**预期收益**：为均值回归逻辑提供明确的空间参考，减少在趋势中段做反转的错误信号。

## 问题 3（中）：CTI 趋势门控逻辑与实盘规律相反

### 现状

`src/features/pipeline.py` 中 CTI（Calm-Trigger Index）的 LONG 触发要求：

```python
trend_ok = (
    (trend_score >= 0.0)   # 4h 趋势向上
    & (rsi_regime >= 0.45)
    & (macd_zone > 0.0)    # 1h MACD 正区间
    & (adx_val > 15.0)
)
```

即 CTI 只在 **顺势** 时激活，逆势时 CTI=0。

### 问题

实盘数据显示：
- AGST（逆势）胜率：v1=40.1%，v1.0.1=39.7%
- WITH（顺势）胜率：v1=32.8%，v1.0.1=28.6%

CTI 作为触发信号之一，在逆势（实际盈利场景）时被强制归零，在顺势（实际失败场景）时才有值。这意味着训练时正样本中 CTI 的分布是扭曲的。

### 建议

有两个选择：
1. **移除趋势门控**：让 CTI 在顺逆势时都有值，由模型自己学习 CTI 与方向的关系
2. **反转门控条件**：改为逆势时激活（与实盘规律一致）

选项 1 更稳妥，选项 2 需要有足够数据验证。

## 问题 5（诊断工具）：缺乏特征重要性分析

### 现状

不清楚当前 137 个特征中哪些真正有预测贡献，哪些是噪音甚至有负贡献。

### 建议

运行 XGBoost 内置的特征重要性分析：

```python
# 查看 gain-based 重要性（最可靠）
import xgboost as xgb
model = xgb.XGBClassifier(...)
model.fit(X_train, y_train)
importance = model.get_booster().get_score(importance_type='gain')
```

或者利用排列重要性（更稳健，但更慢）。

重点关注：
- 当前排名靠前的特征是否符合直觉
- 新加的 `tbr_trend`、`vol_inefficiency` 是否真的进入了重要特征列表
- 是否有大量特征接近 0 贡献（需要清理）

## 改进优先级总览

| 优先级 | 问题 | 类型 | 预计工作量 |
|--------|------|------|----------|
| **P0** | 训练标签与实盘目标对齐 | 标签重构 | 中（需修改 labels.py + 重新 build data + 重训）|
| **P1** | 1h 特征扩充 | 特征工程 | 小（扩展 `_add_medium_features`）|
| **P2** | 价格结构特征 | 特征工程 | 小（加 3~4 个滚动窗口特征）|
| **P3** | CTI 门控逻辑修正 | 特征逻辑 | 小（修改门控条件）|
| **P4** | direction bug 修复效果验证 | 等待数据 | 无需开发，等 v1.0.2.1 数据 |
| **P5** | 特征重要性分析 | 诊断 | 小（运行分析脚本）|

**建议执行顺序**：P5（先诊断再动手）→ P1 → P2 → P0（最大改动，放在后面验证）→ P3

---

## 不建议做的方向

- **时段过滤（21:xx / 07:xx / 13:xx 屏蔽）**：属于策略层补丁，掩盖模型缺陷，不改善预测准确率
- **Cascade 抑制**：同上，是下单策略而非模型改进
- **R-ratio 上限过滤**：同上

以上三项在模型预测准确率超过 50% 之后，可以作为交易策略层的优化考虑。
