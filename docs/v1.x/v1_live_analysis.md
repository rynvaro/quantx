## 三、核心问题分析

### 问题 1：SL 触发速度是 TP 的 2.7 倍（反向进场）

平均止损耗时仅 **13分钟**，而平均止盈耗时 **34分钟**。这说明模型普遍在动量反向时进场，入场后快速被扫损。SL 设置为 0.15%（仅约 3~4 美元），与 ETH 5分钟K线正常波动噪音处于同一量级，相当于"主动送钱"。

### 问题 2：簇状信号 = 无趋势识别能力（最严重）

**案例 A：08:05~08:55 — 7个连续 SHORT，全部 SL**

```
真实行情：2257（低点）→ 2292（反弹）
模型行为：连续做空，逆势被扫
原因判断：RSI超卖后回升 / MACD死叉残留 → 模型滞后1~3根K线仍看空
```

**案例 B：21:05~22:55 — 9个连续 LONG，8个 SL**

```
真实行情：2315 → 2283（下跌约1.4%）
模型行为：连续做多，逆势被扫
原因判断：市场从高点回落，均值回归类指标（BB下轨、RSI<50临界）不断触发多头信号
```

两个案例的共同模式：**趋势持续运动时，模型将"已偏离均值"误判为"即将反转"，并连续发火。**

### 问题 3：LONG 信号密集出现在下跌趋势中

2026-04-20 00:00~06:00 期间，ETH 从 2330 单边下跌至 2257（跌幅 3.1%）。  
这段时间内触发了 **4个 LONG FIRE 信号**，其中 3个 SL，1个 SL（较慢）。

```
00:55  LONG @ 2307 → SL +1bar（次根K线直接破损）
01:35  LONG @ 2305 → SL +3bar（继续下跌至2291）
04:50  LONG @ 2277 → SL +13bar（低位震荡后再跌至2257）
06:05  LONG @ 2257 → SL +2bar（底部确认前再次被扫）
```

触发原因推测：RSI 进入超卖区（<30）、布林带下轨触碰、短期动量背离指标。这些都是典型的**均值回归类滞后指标**，在单边趋势中极易误触。

## 五、改进建议

### 优先级 1：添加趋势过滤器（预计改善最大）

在 `run_signal.py` 信号判断层加入 EMA 趋势门控：

```python
# 伪代码示意
ema20 = feature_row["ema_20"].iloc[-1]    # 20根K线EMA
ema60 = feature_row["ema_60"].iloc[-1]    # 60根K线EMA（1小时）

trend_up   = ema20 > ema60                # 短期均线在长期均线之上
trend_down = ema20 < ema60

# 仅在趋势一致时允许进场
if direction == "LONG"  and not trend_up:   skip()
if direction == "SHORT" and not trend_down: skip()
```

此过滤器可直接拦截案例 A、B 中的全部连续错误信号，预计过滤掉约 60% 的 SL 信号。

### 优先级 2：信号冷却机制

FIRE 后强制等待 **30根K线（150分钟）** 才允许再次触发同方向信号，防止在趋势中连续被扫。

### 优先级 3：扩大止损至 0.4%~0.5%

当前 SL 0.15% 完全在 ETH 5分钟K线噪音范围内。扩大止损后 SL 触发速度下降，有效信号存活率提升。注意需同步重新评估仓位大小（降低每笔保证金比例以控制最大回撤）。

### 优先级 4：提高概率阈值

当前阈值 0.60 → 建议调整为 **0.70**。信号总量从43个减少，但低置信度信号（0.60~0.70 区间）多为误触发。

## 六、结论

v1 模型本质上是一个**无趋势感知的均值回归模型**。在震荡行情中有一定信号质量（TP 存在），但在单边趋势中会连续逆势发火，导致严重亏损。

核心改进路径：**趋势过滤器 > 信号冷却 > SL扩大 > 阈值上调**。

建议在重新训练前先在 `run_signal.py` 层面加入趋势过滤器（不需要重训）做快速验证，再决定是否需要将趋势特征纳入训练特征集（v2 方向）。
