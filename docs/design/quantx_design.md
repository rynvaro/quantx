# QuantX — 小型量化交易系统设计文档

> 作者思路整理 + 技术分析 + 架构方案
> 日期：2026-04-05

---

## 一、核心思路概述

目标是构建一个基于机器学习的**短线加密货币量化交易系统**，核心逻辑如下：

- **数据来源**：通过币安（Binance）等交易所 API 获取实时及历史行情数据
- **特征工程**：将多维指标组合成特征矩阵作为模型输入
- **预测目标**：预测未来 15 分钟内的价格上涨概率及最大涨幅（核心模型：**Model-15m**）
- **交易策略**：仅在预测置信度超过阈值 **且** 预测涨幅超过最低门槛时触发信号；支持**自动执行**或**手动确认后执行**两种模式
- **定位**：非高频交易（HFT），核心是**捕捉买入点**，等待高质量信号，宁可错过也不低质量入场

## 二、指标体系分析

你提出了"二阶指标"和"加速度"的概念，这个方向非常正确。指标可以按阶数分层：

### 2.1 零阶指标（原始数据）

| 指标 | 说明 |
|------|------|
| OHLCV | 开/高/低/收/量，最基础的原始数据 |
| 成交笔数 | 每分钟内的独立成交次数，反映活跃度 |
| 订单簿深度 | 买一/卖一档位及数量，反映即时供需 |
| 资金费率 | 合约市场特有，反映多空力量对比 |
| 买卖成交比 | Taker buy volume / Total volume |

### 2.2 一阶指标（基础技术指标）

| 指标 | 说明 |
|------|------|
| EMA / SMA | 趋势方向，不同周期组合可判断交叉信号 |
| MACD | EMA 差值，本质是趋势动量 |
| RSI | 超买超卖，相对强弱 |
| Bollinger Bands | 波动率通道，均值回归信号 |
| ATR | 平均真实波动幅度，用于衡量波动性 |
| VWAP | 成交量加权均价，机构常用参考价 |

### 2.3 二阶指标（你说的"加速度"，即导数类）

这是你直觉中最有洞见的部分。**价格的一阶导数是动量（momentum），二阶导数才是加速度。**

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| ROC（变化率） | 价格的一阶导数，即动量 | `(P_t - P_{t-n}) / P_{t-n}` |
| 动量加速度 | ROC 的变化速率，即二阶导数 | `ROC_t - ROC_{t-1}` |
| 成交量加速度 | 成交量的变化速率 | `Volume_t / Volume_{t-1} - 1` |
| RSI 斜率 | RSI 的变化速度 | 对 RSI 序列求差分 |
| MACD 斜率 | MACD 柱的加速度 | MACD histogram 的差分 |
| ATR 加速度 | 波动率是否在加剧 | ATR 差分 |
| 订单簿失衡加速度 | 买卖压力变化速率 | OBI 差分 |

### 2.4 高阶 / 复杂指标（已知）

这些指标往往被散户忽视，但在机器学习特征中非常有价值：

| 指标 | 说明 |
|------|------|
| Hurst 指数 | 衡量价格序列的分形特性，>0.5 趋势性市场，<0.5 均值回归市场 |
| 近似熵（ApEn）/ 样本熵 | 衡量价格序列的"可预测性"，熵越低越容易预测 |
| 分形维度 | 价格走势的复杂程度 |
| 自相关系数 | 当前价格与滞后 n 期的相关性，识别周期性规律 |
| ADX（平均方向指数） | 趋势强度，> 25 为趋势行情，< 20 为震荡行情 |
| 跨周期 Tick 流失衡 | 大单与小单分开统计，追踪"聪明钱"方向 |
| 波动率微笑 / 隐含波动率 | 期权市场对未来的预期，如果有期权数据 |
| 情绪指标（Fear & Greed） | 可作为过滤器，不作为主信号 |

### 2.5 实验性自设计指标

> 以下指标基于市场逻辑直觉设计，不全是已被学术或业界正式定义的指标。人类对价格规律的发现远未完成。这些指标的实际价值需要通过 SHAP / feature importance 客观验证，无效的会被剔除。

#### 跨周期相位对齐指数（CPAI）

**直觉**：1m / 5m / 15m 三个时间框架的动量如果方向一致且都在加速，趋势在多个时间尺度上"共振"，可靠性远高于单一周期信号。

```
CPAI = mean(sign(ROC_1m), sign(ROC_5m), sign(ROC_15m))
       × mean(|ROC_1m|, |ROC_5m|, |ROC_15m|)
```

- `CPAI = +1` 且幅度大 → 多框架全面看涨
- `-1 < CPAI < +1` → 时间框架分歧，谨慎入场

---

#### 波动率压缩深度指数（VCDI）

**直觉**：市场像弹簧，压缩越深、持续越久，释放时能量越大。用 ATR 相对历史分布的"压缩百分位"乘以连续压缩时长，衡量即将爆发的能量积蓄程度。

```
atr_pct       = percentile_rank(ATR_14, window=200)
compress_bars = 连续低于 ATR_mean_50 的 K 线数
VCDI          = (1 - atr_pct) × log(1 + compress_bars)
```

- `VCDI > 0.7` → 高度压缩，即将释放，需结合方向指标确认入场方向

---

#### 动量-波动率解耦指数（MVDI）

**直觉**：正常情况下强势价格移动伴随高波动率。若标准化动量远超标准化波动率，说明有"静默大单"在推动价格而没有引发市场恐慌——机构悄悄建仓的典型特征。

```
MVDI = (ROC_5 / σ_ROC_50) / (ATR_14 / mean_ATR_50)
```

- `MVDI > 2.0` 且为正 → 低波动率下的强势上涨 → 看涨
- `MVDI < -2.0` → 低波动率下的静默下跌 → 机构出货

---

#### 价格弹性指数（PEI）

**直觉**：衡量单位成交量推动价格的能力。弹性持续下降说明大量卖单在吸收买盘（阻力墙存在）；弹性由低转高说明卖方耗尽、价格阻力消失（潜在突破前兆）。

```
impact_t = |close_t - open_t| / volume_t
PEI      = EMA(impact, 5) / EMA(impact, 20) - 1
```

- `PEI` 由负转正 → 阻力消耗完毕 → 突破前置信号

---

#### 蜡烛主动力指数（CBFI）

**直觉**：收盘价在 K 线区间内的相对位置反映方向意愿，乘以相对成交量反映意愿强度。高量配高位收盘 = 真实买盘确认；低量配高位收盘 = 可疑"虚涨"。

```
stance   = (close - low) / (high - low)       # 0=收在最低, 1=收在最高
CBFI_t   = (stance - 0.5) × 2 × (volume / mean_volume_20)
CBFI_ema = EMA(CBFI, 5)                       # 平滑后使用
```

---

#### 买卖意愿持久性指数（BSIPI）

**直觉**：单根 K 线的买压可能是噪声，连续多根 K 线 taker_buy_ratio > 0.55 才说明有持续意愿。对持续时长加权，让"持久的中等买压"优于"瞬间的极端买压"。

```
pressure_t    = taker_buy_ratio_t - 0.5
consec_bull   = 连续满足 taker_buy_ratio > 0.55 的 K 线数
BSIPI         = mean(pressure, window=10) × sqrt(consec_bull + 1)
```

- `BSIPI > 0.3` 且上升 → 持续性买压积累 → 买入倾向

---

#### 能量积累相位指数（EARP）

**直觉**：市场在"积累期"（布林带收窄、低波动）和"释放期"（布林带扩张、方向性强）之间循环。积累期末尾——布林带即将由收转扩的时刻——是最佳的买入准备时机。

```
bb_pct   = percentile_rank(BB_width, window=200)
bb_trend = ROC(BB_width, 5)
EARP     = bb_pct × sign(bb_trend)
```

- `EARP` 由负转正（布林带从收窄转为扩张）→ 能量释放启动 → 等待模型方向确认

---

#### 信息不对称指数（IAI）

**直觉**：把 K 线按成交量大小分成"大单"和"小单"。大单（机构/鲸鱼）持续看涨但小单混乱 = 聪明钱悄悄建仓；大单看跌而小单追涨 = 机构向散户派发。

```
is_big    = volume > mean_volume + 1.5 × std_volume
big_dir   = volume_weighted_mean(sign(close - open), where is_big)
small_dir = volume_weighted_mean(sign(close - open), where not is_big)
IAI       = big_dir - small_dir
```

- `IAI > 0` 持续多根 → 大单买入，散户方向混乱 → 聪明钱积累信号

---

#### 趋势分形一致性（TFC）

**直觉**：强趋势中，1m 的价格形态会与 15m 的形态高度相似（自相似性）。两个尺度形态高度相关，说明趋势在不同时间尺度上自我复制，延续概率更高。

```
norm(x)    = (x - min(x)) / (max(x) - min(x))
series_1m  = norm(close_1m.tail(15))
series_15m = norm(interpolate(close_15m[-1], to_length=15))
TFC        = pearson_correlation(series_1m, series_15m)
```

- `TFC > 0.8` 且方向向上 → 趋势分形强烈 → 延续信号

---

### 2.6 大周期趋势指标（滤镜层：1h / 4h / 1d）

这一层的指标**不用于寻找买入点，而是作为趋势滤镜（Trend Filter）**。在大趋势方向支持下才允许 Model-15m 信号触发，这叫做 **Trend Alignment（趋势对齐）**。

| 指标 | 时间框架 | 说明 |
|------|---------|------|
| EMA 多空排列 | 4h | EMA9 > EMA21 > EMA55 = 多头排列，为 15m 买入提供背书 |
| ADX 趋势强度 | 4h | > 25 = 有方向性趋势；< 20 = 震荡，慎重 |
| MACD histogram 区间 | 1h | 持续正值 = 日内大趋势向上 |
| RSI 区制 | 4h | > 50 = 多头区制；< 50 = 空头区制 |
| 价格相对 EMA200 | 1d | 价格在日线 EMA200 上方 = 宏观多头背景 |
| 周区间价格位置 | 1d | `(close - week_low) / (week_high - week_low)`，0=周低位，1=周高位 |

**Trend Alignment 信号增强规则**（未来可扩展为特征，当前先作为过滤器）：

```python
trend_aligned = (
    EMA_alignment_4h == "bullish"  and   # 4h EMA 多头排列
    ADX_4h > 20                    and   # 4h 有方向性
    RSI_4h > 50                    and   # 4h 多头区制
    MACD_hist_1h > 0                     # 1h 看涨
)
# 只有 trend_aligned=True 时，Model-15m 信号才触发交易
```

---

> **结论**：指标体系分为五层——零阶（原始数据）→ 一阶（技术指标）→ 二阶（加速度族）→ 高阶（已知复杂指标 + 自设计实验性指标）→ 大周期趋势滤镜。通过 SHAP 分析客观筛选，形成最终输入矩阵。

## 三、需要指正的问题

### 3.1 ❌ "不关注热点事件"有重大风险

**你说**：只根据指标就可以大致预测，不需要关注热点事件。

**问题所在**：加密货币市场对宏观事件高度敏感。黑天鹅事件（监管政策、交易所暴雷、巨鲸操作）会在几秒内击穿所有技术指标的预测。

**建议**：
- 将**新闻/事件过滤器**作为系统的保护层，而非主信号
- 至少加入"重要事件日历"，在重大事件前后暂停交易
- 可以接入加密货币新闻 API（如 CryptoPanic）做实时情绪监控

### 3.2 ❌ "70% 置信度"需要校准，不能直接用原始模型输出

**你说**：预测涨的概率是 70% 就入场。

**问题所在**：神经网络/XGBoost 等模型的原始输出概率未必是经过校准的真实置信度。模型说 70% 可能实际上只有 55%。

**建议**：
- 使用 **Platt Scaling** 或 **Isotonic Regression** 对模型概率进行校准
- 在回测中统计：当模型输出 [0.65, 0.75] 时，实际胜率是多少

### 3.3 ✅ 交易成本问题：已通过策略设计规避（仍需量化）

**策略澄清**：你明确不做涨幅小的交易，只在预测到有意义幅度时才入场。这个决定非常正确，直接规避了手续费蚕食利润的最大陷阱。

**仍需注意**：
- 币安双向手续费约 0.2%，建议**最低入场门槛设在预测涨幅 > 0.8%**，为滑点留出空间
- 回测时必须扣除手续费和滑点，不能用毛利润评估策略
- 涨幅门槛不宜设太高（如 > 3%），否则信号极少，样本量不足以验证模型稳定性

### 3.4 ⚠️ 标签定义需要精确

**问题**：如果用"15 分钟后收盘价涨跌"作为标签，噪声极大。K 线收盘价只是 15 分钟内最后一个点，中途可能已经涨到目标价再跌回去，但用收盘价会把它标记为"跌"。

**Model-15m 的标签定义（推荐）**：

- **分类标签**：未来 15 分钟内，区间最高点的涨幅是否超过最低入场门槛（0.8%）
  ```
  y_class = 1  如果 max(close[t+1:t+15]) / close[t] - 1 >= 0.8%
  y_class = 0  否则
  ```
- **回归标签**：未来 15 分钟内的最大浮盈幅度
  ```
  y_reg = max(close[t+1:t+15]) / close[t] - 1
  ```

用区间**最高点**而非收盘价，是因为交易目标是"在高点止盈"，这与实际交易场景完全一致。

## 四、系统架构设计

```
┌─────────────────────────────────────────────────────────┐
│                      QuantX System                       │
│                                                          │
│  ┌──────────────┐    ┌──────────────┐    ┌───────────┐  │
│  │  数据采集层   │───▶│  特征工程层   │───▶│  模型层   │  │
│  └──────────────┘    └──────────────┘    └───────────┘  │
│          │                                      │         │
│  ┌──────────────┐                    ┌──────────────────┐│
│  │  数据存储层   │                    │    交易执行层     ││
│  └──────────────┘                    └──────────────────┘│
└─────────────────────────────────────────────────────────┘
```

### 4.1 数据采集层

- **Binance REST API**：拉取历史 K 线（OHLCV），用于训练
- **Binance WebSocket**：订阅实时 K 线、订单簿、逐笔成交流，用于推理
- **数据周期**：独立拉取 1m / 5m / 15m / 1h / 4h 全部 K 线（不依赖聚合，独立拉取更精确）
- **建议存储**：SQLite（轻量本地）或 InfluxDB（时序数据库）

### 4.2 特征工程层

#### 多时间框架输入与趋势对齐（Trend Alignment）

Model-15m 采用**多时间框架输入（Multi-Timeframe）**，核心理念是：**在大趋势支撑下预测小趋势，成功率显著高于只看单一周期**（Trend Alignment）。小周期信号在大趋势方向一致时才可靠。

| 粒度 | 回看窗口 | 覆盖时长 | 特征类型 | 作用 |
|------|--------|--------|--------|------|
| 1m K线 | 最近 30 根 | 30 分钟 | 完整多阶特征 | 短期动量、入场前走势细节 |
| 5m K线 | 最近 24 根 | 2 小时 | 完整多阶特征 | 中期趋势方向 |
| 15m K线 | 最近 16 根 | 4 小时 | 完整多阶特征 | 中大周期背景、支撑/阻力 |
| 1h K线 | 最近 24 根 | 1 天 | 仅趋势性指标 | 日内大趋势、RSI区制 |
| 4h K线 | 最近 30 根 | 5 天 | 仅趋势性指标 | 多日宏观趋势背景、ADX强度 |

1m / 5m / 15m 计算完整多阶特征；**1h / 4h 仅提取趋势性指标**（EMA 排列、ADX、RSI 区制、MACD 区间方向），不计算短期加速度类指标（在大周期上无意义）。

> **为什么不用秒级数据**：对于 15 分钟的预测窗口，1 秒内的抖动是纯噪声。秒级数据只对预测"下一秒"有意义，用于 15m 预测只会拖累信噪比，不会带来收益。

---

#### 滑窗样本构造（训练数据生成）

训练数据的核心构造方式——在历史时间轴上滑动窗口，生成大量 `(特征矩阵, 标签)` 样本对：

```
历史数据时间轴：

... ──[──────────────────────]──────────────── ...
              ↑                  ↑         ↑
         窗口计算起点          时间点 t   t + 15min

  输入 X_t：时间点 t 之前的多时间框架特征矩阵
            （1m×30 + 5m×24 + 15m×16 + 1h×24 + 4h×30）

  标签 y_t：[t, t+15min] 区间内的最大涨幅
            分类标签：max_gain >= 0.8% → 1，否则 → 0
            回归标签：max_gain 的具体数值
```

沿时间轴每隔 1 分钟滑动一步，生成大量 `(X_t, y_t)` 样本对。1 年历史数据约产生 **50 万条样本**，经标签过滤（去掉极端行情异常点）后约保留 30 万条。

**关键约束：标签只能用 t 之后的数据；特征只能用 t 及之前的数据。** 任何违反此规则的操作都会造成"未来数据泄漏"，导致回测虚高、模型实盘失效。

---

#### 特征计算示意

```python
# 1m / 5m / 15m：计算完整多阶特征
def compute_full_features(df):
    return {
        # 零阶
        "taker_buy_ratio": df.taker_buy_vol / df.volume,
        # 一阶
        "ema_fast":  EMA(df.close, 9),
        "ema_slow":  EMA(df.close, 21),
        "rsi_14":    RSI(df.close, 14),
        "macd_hist": MACD(df.close).histogram,
        "atr_14":    ATR(df.high, df.low, df.close, 14),
        "bb_width":  BollingerBandWidth(df.close, 20),
        # 二阶（加速度族）
        "roc_5":       ROC(df.close, 5),
        "roc_accel":   DIFF(ROC(df.close, 5)),
        "rsi_slope":   DIFF(RSI(df.close, 14)),
        "volume_accel":DIFF(df.volume),
        "macd_accel":  DIFF(MACD(df.close).histogram),
        # 高阶（已知）
        "hurst":   HurstExponent(df.close, window=100),
        "entropy": SampleEntropy(df.close, window=50),
        # 高阶（自设计，按 2.5 节定义计算）
        "vcdi":  VCDI(df),
        "mvdi":  MVDI(df),
        "pei":   PEI(df),
        "cbfi":  CBFI(df),
        "bsipi": BSIPI(df),
        "earp":  EARP(df),
        "iai":   IAI(df),
        "tfc":   TFC(df),
    }

# 1h / 4h：仅提取趋势性指标
def compute_trend_features(df):
    return {
        "ema_align":      int(EMA(df.close,9)[-1] > EMA(df.close,21)[-1] > EMA(df.close,55)[-1]),
        "adx":            ADX(df.high, df.low, df.close, 14)[-1],
        "rsi_regime":     RSI(df.close, 14)[-1] / 100,
        "macd_zone":      float(np.sign(MACD(df.close).histogram[-1])),
        "price_vs_ema200":df.close[-1] / EMA(df.close, 200)[-1] - 1,
    }

# 当前时间点 t 的特征矩阵构造（推理时同样适用）
X_t = {
    **prefix("1m",  compute_full_features(df_1m.iloc[:t].tail(30))),
    **prefix("5m",  compute_full_features(df_5m.iloc[:t].tail(24))),
    **prefix("15m", compute_full_features(df_15m.iloc[:t].tail(16))),
    **prefix("1h",  compute_trend_features(df_1h.iloc[:t].tail(24))),
    **prefix("4h",  compute_trend_features(df_4h.iloc[:t].tail(30))),
}
```

- 所有特征做 **Z-Score 归一化**（按训练集统计量，推理时复用同一 scaler，不重新计算）

### 4.3 模型层：Model-15m

#### 4.3.1 模型定位

Model-15m 是系统的核心模型，推理流程如下：

```
实时数据 → 多时间框架特征 → 模型推理 → 输出信号 → [手动/自动] → 下单
```

**双头输出**（需同时满足才触发信号）：
- **分类头**：`P(涨@15m)` — 未来 15 分钟内涨幅超过门槛的概率，校准后 > 65% 才考虑入场
- **回归头**：`Δmax@15m` — 预测的最大涨幅，> 0.8% 才考虑入场

#### 4.3.2 模型架构

推荐使用 **Transformer + 双头输出**。Transformer 的自注意力机制能捕捉多时间步之间的非线性依赖，对多时间框架拼接输入的处理能力优于 LSTM。

```
多时间框架特征 (1m×30 + 5m×24 + 15m×16)
       ↓ 拼接 + Position Encoding
  Transformer Encoder（4层，8头注意力）
       ↓
  共享表示层（全连接 + LayerNorm）
      ↙                  ↘
分类头（Sigmoid）       回归头（Linear）
P(涨@15m)              Δmax@15m
```

> **初期可先用 XGBoost 替代 Transformer** 跑通完整流程并验证特征有效性，XGBoost 不需要 Position Encoding，直接将拼接后的特征向量输入即可。验证特征有价值后再升级为 Transformer。

#### 4.3.3 训练策略

- **Walk-forward 验证**（必须，禁止 K-Fold）：
  - 训练窗口：历史 6 个月
  - 验证窗口：紧跟训练集之后的 1 个月
  - 滚动步长：每月重训一次，保持模型对近期市场状态的适应性
- **损失函数**：
  - 分类头：Binary Cross-Entropy（正负样本不均衡时对正样本加权）
  - 回归头：Huber Loss（对极端涨幅异常值不敏感）
  - 联合损失：`L = L_class + λ × L_reg`，λ 初始设为 0.5，可调
- **防过拟合**：
  - Dropout（0.2～0.3）
  - L2 正则化（weight_decay = 1e-4）
  - Early Stopping（监控验证集 F1，patience=10）
  - 训练后剔除特征重要性低于 1% 的特征，减少噪声维度

#### 4.3.4 模型概率校准

模型分类头的原始输出不是经过校准的概率，不能直接用于决策阈值判断。训练完成后必须做校准：

- 用**验证集**跑 **Platt Scaling** 或 **Isotonic Regression**
- 校准后在验证集上统计分桶胜率：当校准概率处于 [0.60, 0.70]、[0.70, 0.80] 时，实际胜率分别是多少
- 根据统计结果设定真实的入场概率阈值，而非凭感觉定 70%

#### 4.3.5 评估指标

不使用 Accuracy（在正负样本不均衡时毫无意义）：

| 指标 | 含义 | 目标 |
|------|------|------|
| Precision（精确率） | 触发信号时真的能涨的比例 | > 60% |
| Recall（召回率） | 所有真实上涨机会中被捕捉到的比例 | 不是核心，宁可错过 |
| F1 Score | Precision 与 Recall 的调和均值 | 监控训练过程用 |
| IC（信息系数） | 预测涨幅与实际涨幅的 Spearman 相关系数 | > 0.05 即有统计意义 |
| 回测夏普比率 | 风险调整后的收益 | > 1.0 |

> **Precision 比 Recall 更重要**。系统的定位是"宁可错过，不要误入"，高 Precision 低 Recall 是符合策略目标的。

#### 4.3.6 回测与验证

- **Walk-forward validation** 滚动回测，防止未来数据泄漏
- **禁止 K-Fold**：K-Fold 会让未来数据污染训练集，导致回测虚高
- **必须扣除手续费和滑点**（用 0.15% 单边，即保守估计）
- 关注指标：**夏普比率、最大回撤、胜率、盈亏比**

### 4.5 交易执行层

- **信号触发条件**（需同时满足）：
  1. 模型校准概率 > 阈值（通过回测确定，建议从 65% 开始调参）
  2. 模型预测涨幅 > 最低门槛（建议 0.8%，通过回测调整）
- **执行模式**：
  - **自动模式**：条件满足即自动下单，适合已验证稳定的策略
  - **手动模式**：收到信号提醒后人工判断是否入场，适合初期验证和行情异常时
  - 建议初期始终开启手动模式，积累足够置信度后再切自动
- **仓位管理**：固定比例（如每次用总资金的 10%～20%），不用凯利公式（风险较高）
- **止损**：必须设置硬止损，例如 ATR 的 1.5 倍
- **止盈**：达到预测目标幅度的 80% 时提前止盈，不贪心

### 5.1 技术可行性

**完全可行**。类似系统已有大量开源实现，币安 API 文档完善，Python 生态（`ccxt`, `pandas-ta`, `sklearn`, `pytorch`）工具链成熟。一个人可以在 2-3 个月内完成 MVP。

### 5.2 盈利可行性

**有可能，但比你想的难得多**。

| 维度 | 评估 |
|------|------|
| 市场效率 | 加密市场效率低于股票市场，短期可预测性相对更强 ✅ |
| 竞争对手 | 大量专业量化团队在做同样的事，but 你的定位是辅助买点判断，而非全自动对抗 ⚠️ |
| 过拟合风险 | 特征多 + 数据少 = 极容易过拟合，回测漂亮但实盘亏损 ❌高危 |
| 市场状态切换 | 牛/熊/横盘三种状态，模型在一种状态训练，换状态可能失效 ⚠️ |
| 黑天鹅防护 | 如果没有事件过滤器，极端行情一次就能清仓 ❌高危 |
| 手动模式缓冲 | 支持手动确认，人工判断可过滤掉一部分明显异常信号 ✅ |

**策略调整后的成功概率重估**：

相比原始方案，以下调整显著提升了概率：
- ✅ **不追小波动**：手续费占利润比率大幅降低，每笔交易的期望值更高
- ✅ **高选择性入场**：减少过度交易，信号变少但质量更高
- ✅ **手动模式作为安全网**：初期可用人工判断过滤掉模型不可信的信号

| 目标 | 原方案 | 调整后 |
|------|--------|--------|
| 长期稳定盈利（夏普 > 1） | 15%～25% | **25%～35%** |
| 偶尔盈利、总体保本 | 40%～50% | **50%～60%** |
| 前 6 个月出现较大亏损 | 50% | **35%** |

> 这不是在泼冷水，而是行业现实。专业量化基金团队做到夏普 > 1.5 就已经是顶级了。作为个人项目，**能做到正期望（长期盈利）就已经优于 95% 的散户**。概率的提升来自于更合理的策略设计，但过拟合和黑天鹅风险依然是最需要防守的两个点。

### 5.3 建议的成功路径

1. **第一阶段（验证想法）**：用历史数据回测，不跑实盘，验证特征是否有预测力（用 IC 信息系数衡量）
2. **第二阶段（模拟盘验证）**：接实时数据但不下单，观察模型在真实市场的表现，持续 1 个月
3. **第三阶段（小仓实盘）**：用极小仓位（$100 以内）验证系统执行的正确性
4. **第四阶段（正式运行）**：根据回撤和夏普比率逐步加仓

## 八、总结

你的核心直觉是正确的：**用多阶技术指标（包括"加速度"类导数指标）作为特征，训练机器学习模型寻找买入点**，这是主流量化策略的合理子集。特别是你提出的"二次导数"特征，是很多散户系统缺失的维度。

更新后的策略定位更加清晰：**系统不是全自动交易机器，而是一个买点信号系统**。模型负责从海量历史模式中识别高概率买入时机，人工或自动负责执行。这种定位降低了对模型精度的极端依赖，也给了你足够的空间在初期用手动模式积累信心。

主要需要注意的风险点：
1. **过拟合** 是最大敌人，Walk-forward 验证必须严格执行
2. **极端事件过滤** 不能省，否则会在黑天鹅事件中被清仓
3. **最低涨幅门槛** 必须通过回测量化，不能靠感觉设定
4. **模型概率校准** 不能用原始输出直接决策

按上述架构实施，这个系统是完全可以落地的。

## 九、扩展方向（待 Model-15m 稳定后实施）

> 本节内容暂不实施，仅作为未来规划存档。

### 9.1 其他预测时间框架模型

架构设计与 Model-15m 完全相同，仅调整输入窗口和标签定义：

| 模型 | 预测目标 | 输入窗口 | 分类标签门槛 | 备注 |
|------|---------|---------|------------|------|
| Model-5m | 未来 5 分钟最大涨幅 | 1m×20 + 5m×12 | ≥ 0.5% | 信号更频繁，可作为 15m 的辅助确认 |
| Model-1m | 未来 1 分钟方向 | 1m×30 | — | 噪声极大，慎用，仅研究性质 |

> Model-1m 不建议用于实盘交易，1 分钟的价格几乎不可预测，探索时应格外谨慎。

### 9.2 多时间框架联合输出方案（Scheme B）

单模型同时输出多个时间窗口的预测，共享底层特征提取：

```
输入特征 → Transformer → [P(涨@5m), Δmax@5m, P(涨@15m), Δmax@15m]
```

**优点**：
- 参数量更小（共享底层表示）
- 不同时间窗口的预测互相约束，理论上更稳定
- 可以用"5m 和 15m 同时看涨"作为更强的入场过滤条件

**缺点**：
- 标签构造更复杂
- 联合损失函数需要调参多个 λ 权重
- 训练难度和调试难度更高

**建议**：等 Model-15m 在实盘模拟中验证稳定后再考虑升级，不要在验证期引入额外复杂度。

### 9.3 集成模型（Ensemble）

多个不同架构的模型（XGBoost + LSTM + Transformer）独立预测，通过投票或加权平均输出最终信号。稳定性最好，但维护成本最高，作为最终形态考虑。
